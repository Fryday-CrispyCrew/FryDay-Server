== 사용자(User)

=== 소셜 로그인 (카카오, 네이버)
`POST /api/users/social/login`

카카오, 네이버 소셜 로그인을 처리합니다. Access Token 기반 인증을 사용합니다.

==== 온보딩 상태 (OnboardingStatus)

응답의 `onboardingStatus` 필드는 사용자가 다음에 어떤 화면으로 이동해야 하는지를 나타냅니다.

[cols="1,3,2"]
|===
|상태 |설명 |다음 화면

|`NEEDS_AGREEMENT`
|약관 동의가 필요한 상태 (최초 가입 첫 단계)
|약관 동의 화면

|`NEEDS_NICKNAME`
|닉네임 설정이 필요한 상태 (두 번째 단계)
|닉네임 설정 화면

|`NEEDS_ONBOARDING`
|온보딩 화면 확인이 필요한 상태 (세 번째 단계)
|온보딩 화면

|`COMPLETED`
|모든 설정이 완료된 상태 (정상 로그인)
|메인 화면
|===

NOTE: 온보딩은 NEEDS_AGREEMENT → NEEDS_NICKNAME → NEEDS_ONBOARDING → COMPLETED 순서로 진행됩니다.

NOTE: `instanceId`는 `GET /api/todos` 응답의 `data[].id` 필드입니다. 반복 투두도 날짜별로 독립된 인스턴스 ID를 가집니다.

NOTE: 기존 `PATCH /api/todos/recurrence/{recurrenceId}` API는 단순 규칙 전체 교체만 지원합니다. 이번 API는 scope를 지정해 "이번만 / 이후 전체 / 전체" 중 하나로 세밀하게 수정할 수 있습니다. 반복 투두 수정은 이 API를 사용하세요.

==== scope별 동작

[cols="1,2,3"]
|===
|scope |UI 문구 예시 |동작

|`THIS`
|이번 일정만 수정
|해당 인스턴스에만 override 값이 저장됩니다. 반복 규칙과 다른 인스턴스는 변경되지 않습니다.

|`THIS_AND_FUTURE`
|이번 일정 이후 모든 반복 일정 수정
|선택한 날짜부터 반복 규칙이 분기됩니다. 기존 규칙은 선택한 날짜 하루 전에 종료되고, 새로운 규칙이 해당 날짜부터 시작됩니다.

|`ALL`
|전체 반복 일정 수정
|반복 규칙 자체를 수정합니다. 개별적으로 수정된 인스턴스(`isOverridden=true`)는 override 값이 유지됩니다.
|===

==== payload 필드 구성

`payload`는 **content 필드**와 **rule 필드**로 나뉩니다. 모두 선택사항이며, 변경하고 싶은 필드만 포함하면 됩니다.

[cols="1,1,1,3"]
|===
|필드 |구분 |THIS에서 |설명

|`title`
|content
|적용
|제목

|`memo`
|content
|적용
|메모

|`isAlarmEnabled`
|content
|적용
|알람 활성화 여부

|`alarmTime`
|content
|적용
|알람 시간 (HH:mm:ss)

|`type`
|rule
|**무시됨**
|반복 주기 (`DAILY` / `WEEKLY` / `MONTHLY` / `YEARLY`)

|`frequencyValues`
|rule
|**무시됨**
|반복 상세 값. WEEKLY → `["MONDAY", "WEDNESDAY"]`, MONTHLY/YEARLY → `["15"]` 형식

|`startDate`
|rule
|**무시됨**
|반복 시작일 (YYYY-MM-DD). `scope=ALL` 에서만 유효

|`endDate`
|rule
|**무시됨**
|반복 종료일 (YYYY-MM-DD). 생략하거나 필드 자체를 넣지 않으면 기존 종료 조건을 유지합니다.
|===

NOTE: `scope=THIS`에서 rule 필드(`type`, `frequencyValues`, `startDate`, `endDate`)는 서버에서 무시됩니다. +
`scope=ALL`에서 `startDate`를 변경하면 오늘 이후 인스턴스가 삭제되고 새 규칙으로 재생성됩니다.

=== 그룹 참여
`POST /api/groups/join`

초대 코드로 그룹에 참여합니다.
그룹마다 최소 1개의 카테고리를 공개해야 하므로, 참여와 공개 카테고리 설정을 한 번의 요청으로 함께 처리합니다.
카테고리를 하나도 선택하지 않으면 참여할 수 없습니다(400).

존재하지 않는 초대 코드는 404, 이미 참여 중이거나 정원(10명)이 찬 그룹은 409 로 응답합니다.

=== 그룹 조회
`GET /api/groups/{groupId}`

그룹 정보와 그룹원 목록을 한 번에 조회합니다.
그룹원마다 자신이 이 그룹에 공개한 카테고리 기준으로 오늘의 전체 투두 수와 완료 수를 함께 내려줍니다.
그룹장은 항상 목록의 첫 번째이며, 나머지 그룹원은 참여한 순서대로 정렬됩니다.

그룹원마다 오늘의 영업 상태(`status`)와 지금 보낼 수 있는 상호작용(`availableInteraction`)도 함께 내려줍니다.
앱은 이 값을 그대로 화면에 반영하면 됩니다.

|===
| `status` | 상태 | 조건 | `availableInteraction`

| `BEFORE_OPEN`
| 영업 전
| 공개 카테고리의 오늘 투두가 0개
| `KNOCK` (똑똑똑)

| `PREPARING`
| 영업 준비
| 투두가 1개 이상 있고, 완료한 투두는 0개
| `ORDER` (주문이요)

| `FRYING`
| 튀김 조리 중
| 1개 이상 완료, 전부 완료는 아님
| `DELICIOUS` (맛있어요)

| `CLOSED`
| 영업 종료
| 전부 완료
| `APPLAUSE` (박수)
|===

=== 그룹 상호작용
`POST /api/groups/{groupId}/members/{targetUserId}/interactions`

다른 그룹원에게 상호작용(똑똑똑, 주문이요, 맛있어요, 박수)을 보내고, 받는 사람에게 푸시 알림을 보냅니다.
보낼 수 있는 상호작용은 받는 사람의 영업 상태에 따라 하나로 정해지며, 그룹 조회 응답의 `availableInteraction` 값을 그대로 보내면 됩니다.

같은 그룹원에게 같은 상호작용은 30초에 한 번만 보낼 수 있습니다. 다른 상호작용이나 다른 그룹원에게는 바로 보낼 수 있습니다.
받는 사람이 이 그룹의 알림을 껐다면 요청은 성공하지만 알림은 가지 않습니다.

|===
| 상황 | 상태 코드

| 자신에게 보냄
| 400

| 보내는 사람이나 받는 사람이 그룹원이 아님
| 404

| 받는 사람의 영업 상태가 바뀌어 상호작용이 맞지 않음 (화면을 새로고침해 최신 상태를 받아야 합니다)
| 409

| 30초가 지나지 않음
| 429
|===

=== 그룹 이벤트 스트림 (SSE)
`GET /api/groups/{groupId}/events`

그룹 화면에 있는 동안 다른 그룹원의 변경을 실시간으로 받는 SSE(Server-Sent Events) 연결입니다.
그룹 화면에 진입할 때 연결하고, 화면을 벗어나면 연결을 끊으면 됩니다.

이벤트에는 바뀐 데이터가 담기지 않습니다. 이벤트를 받으면 그룹 조회 API를 다시 호출해 화면을 갱신하면 됩니다.

|===
| 이벤트 | data | 보내는 때

| `connected`
| `ok`
| 연결 직후 1회

| `group-progress`
| `{"memberUserId": 변경한 그룹원 ID}`
| 그룹원이 투두를 추가·완료·취소·삭제·이동하거나 공개 카테고리를 변경했을 때

| (comment)
| `:ping`
| 25초마다. 연결 유지용이므로 무시하면 됩니다
|===

클라이언트 규약입니다.

* 연결과 재연결 직후에는 이벤트를 기다리지 말고 무조건 그룹 조회 API를 다시 호출합니다. 끊긴 동안의 변경은 다시 보내주지 않습니다(`Last-Event-ID` 미지원).
* 연결은 30분 뒤 서버가 끊습니다. 화면에 계속 있다면 다시 연결하면 됩니다. 서버 배포 중에도 끊길 수 있습니다.
* 날짜가 바뀌면(자정) 그룹 조회 응답의 `date` 값과 비교해 다시 호출합니다. 자정에는 별도 이벤트가 오지 않습니다.
* 실패 응답은 상태 코드로만 판단합니다. 본문은 없습니다. 그룹원이 아니면 404입니다.

=== 그룹 푸시 알림

그룹에서 일어난 일을 그룹원에게 FCM 푸시로 알립니다. 행동한 본인, 이 그룹의 알림을 끈 그룹원, 기기의 앱 알림을 끈 사용자에게는 보내지 않습니다.

알림을 눌렀을 때 이동할 화면을 정할 수 있도록 FCM `data` 에 아래 값을 함께 담습니다.
FCM 규격상 `data` 의 키와 값은 모두 문자열입니다.

|===
| 키 | 설명

| `type`
| 알림 종류. 아래 표의 값 중 하나입니다

| `groupId`
| 관련 그룹 ID. 해당 그룹이 남아 있는 알림에만 들어갑니다

| `interactionType`
| 상호작용 종류(`KNOCK`, `ORDER`, `DELICIOUS`, `APPLAUSE`). `GROUP_INTERACTION` 알림에만 들어갑니다
|===

|===
| `type` | 보내는 때 | 받는 사람 | 제목 | 본문 | `groupId` | 눌렀을 때 이동

| `GROUP_JOINED`
| 새 사용자가 그룹에 참여
| 참여자를 뺀 그룹원
| 그룹명
| `[닉네임]님이 그룹에 참여했습니다.`
| 있음
| 그룹 상세

| `GROUP_DISBANDED`
| 그룹장이 그룹을 해체하거나 회원 탈퇴해 그룹이 해체됨
| 그룹장을 뺀 그룹원
| 그룹명
| `[그룹명]이(가) 해체되었습니다.` (받침에 맞춰 조사를 붙입니다)
| 없음
| 그룹 목록

| `GROUP_FRYING_STARTED`
| 그룹원이 오늘 처음으로 공개 카테고리 투두를 완료
| 완료한 그룹원을 뺀 그룹원
| 그룹명
| `[닉네임]님이 튀김을 튀기기 시작했어요!`
| 있음
| 그룹 상세

| `GROUP_FRYING_FINISHED`
| 그룹원의 오늘 공개 카테고리 투두가 전부 완료
| 완료한 그룹원을 뺀 그룹원
| 그룹명
| `[닉네임]님이 튀김을 다 튀겼습니다!`
| 있음
| 그룹 상세

| `GROUP_INTERACTION`
| 다른 그룹원이 상호작용을 보냄
| 상호작용을 받은 그룹원 한 명
| 그룹명
| 똑똑똑 `[닉네임]님이 똑똑똑 두드렸어요!`, 주문이요 `[닉네임]님이 주문을 넣었어요!`, 맛있어요 `[닉네임]님이 맛있대요!`, 박수 `[닉네임]님이 박수를 보냈어요!`
| 있음
| 그룹 상세
|===

`GROUP_FRYING_STARTED` 와 `GROUP_FRYING_FINISHED` 는 그룹원마다, 그룹마다 하루에 한 번만 보냅니다(Asia/Seoul 기준).

* 공개 카테고리는 그룹마다 다르므로 그룹별로 따로 판단합니다.
* 오늘 공개 투두가 1개뿐이면 완료하는 순간 전부 완료가 되므로 `GROUP_FRYING_FINISHED` 만 보냅니다.
* 완료를 취소했다가 다시 완료해도 같은 날에는 다시 보내지 않습니다.
* `GROUP_FRYING_FINISHED` 는 완료 체크뿐 아니라, 남은 투두를 삭제하거나 다른 날짜나 비공개 카테고리로 옮겨 전부 완료가 된 경우에도 보냅니다.

앞으로 알림 종류가 늘어나도 `type` 으로 구분합니다. 앱은 모르는 `type` 을 받으면 기본 화면을 열면 됩니다.
